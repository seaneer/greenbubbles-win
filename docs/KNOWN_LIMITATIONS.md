# 已知限制

接线前请先读这一页。以下都是实测结论，不是猜测。

## 平台与账号

| 限制 | 影响 | 规避 |
| --- | --- | --- |
| 仅 Windows + 微信 4.x（实测 4.1.11.24） | 其他平台 / 3.x 不适用 | — |
| 取新密钥需要微信处于登录运行状态 | 微信退出后首次使用会失败 | 已有 `state/keys.json` 时仍可读旧库 |
| 仅支持本机已登录账号 | 不能读他人账号 | 设计如此 |
| 微信升级可能改变内存布局或库结构 | 密钥捕获 / 解密失败 | 先跑 `source status`；失败时等适配 |

## 数据完整性

| 限制 | 影响 | 规避 |
| --- | --- | --- |
| 语音（`msg_type 34`）未解码 | 只有 `Voice` 占位 | 暂不支持，需要 silk 解码器 |
| `wxgf` 是 HEVC 容器，需要转码才能当图片看 | 直接打开是二进制 | 连接器会校验并给出 `image/heif`；本机有 `ffmpeg` 时用它判断 XOR key，转码可自行执行 `ffmpeg -f hevc` |
| 微信未下载的附件拿不到 | `media.available=false` / HTTP 404 | 先在微信里打开该消息，再重试 |
| 公众号会话（`gh_*`）出现在会话列表，但可能没有对应消息表 | `messages` 返回 `conversationNotFound`，`ok` 仍为 `true`，`coverageComplete=false` | 改用群聊/联系人会话查询；不要把空结果当成功 |
| 同一 `sort_seq` 可能存在多条（分片迁移） | 不同入口去重口径不同 | 统一按 `(sort_seq, local_id)` 去重；精确取用 `message get` |
| 27/45 张 PNG 缺 IEND 等尾部 | 部分查看器报警 | 先确认不是 XOR key 选错（连接器现在会自动校验并重试 0..255）；确认后再按实际扩展名保存 |

## 搜索与性能

| 限制 | 影响 | 规避 |
| --- | --- | --- |
| 未建索引时全库搜索 48–65 秒 | Agent 超时 | 先 `index build`；或带 `conversation`（约 1.5 秒） |
| 索引可能滞后于新消息 | 搜不到刚收到的内容 | 增量 `index build`（只补新行） |
| 索引约占 380 MB | 磁盘占用 | 删除 `state/search-index.sqlite3` 即回退实时扫描 |
| 单页上限 500 | 以为取全了其实没有 | 必读 `page.hasMore` / `nextCursor` |
| CLI 每次启动 1.3–1.5 秒 | 高频调用慢 | 用长驻 HTTP |

## 契约细节

| 限制 | 影响 | 规避 |
| --- | --- | --- |
| 会话不存在仍 `ok:true` | 容易误判成功 | 检查 `warnings[].code` 与 `coverageComplete` |
| `--format jsonl` 的游标在 stderr | 只读 stdout 会丢翻页 | 0.2.1 起 stderr 打印 `nextCursor=` |
| 无增量推送 | 只能轮询 | 定时任务 + `since` 游标 |
| 时间按 `+08:00` 解释 | 跨时区调用需显式带偏移 | 传 ISO 8601 带时区 |

## 安全边界

| 限制 | 影响 | 规避 |
| --- | --- | --- |
| `state/keys.json` 等同密码 | 泄露即可解全部历史 | 磁盘加密；不要提交、不要上传 |
| HTTP 默认仅监听回环 | 跨机访问不通 | 用 SSH 隧道；A 模式可显式绑 `0.0.0.0`，仅限可信内网 |
| 快照口令只显示一次 | 丢失无法恢复 | 当场抄写，与 vault 分开保存 |
